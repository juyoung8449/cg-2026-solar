# 📌 WebGL 행렬 변환 순서에 따른 자전 및 공전 구현 보고서

## 1. 개요

3D 그래픽스에서 정점(Vertex) 위치 벡터에 변환 행렬을 곱할 때, 행렬 연산의 적용 순서에 따라 물체의 최종 위치 및 움직임 형태(자전 vs 공전)가 어떻게 변화하는지 비교·분석한다.

---

## 2. 핵심 원리: 행렬과 벡터 곱의 "오른쪽부터 적용"

3D 공간의 정점 위치 벡터 $\mathbf{p}$에 변환 행렬을 곱할 때의 기본 수식은 다음과 같다.

$$\mathbf{p}' = \mathbf{M} \cdot \mathbf{p}$$

두 개의 변환 행렬 $A$와 $B$를 곱하여 하나의 Model 행렬을 구성할 때 연산 순서는 아래와 같이 전개된다.

$$\mathbf{p}' = (A \cdot B) \cdot \mathbf{p} = A \cdot (B \cdot \mathbf{p})$$

* **연산 순서:** 괄호의 결합 법칙에 의해 정점 벡터 $\mathbf{p}$와 **가장 가까운 오른쪽 행렬 $B$가 먼저 적용**된 후, 그 결과에 **왼쪽 행렬 $A$가 순차적으로 적용**된다.

---

## 3. 연산 순서에 따른 동작 비교

### ① 제자리 회전 (자전, Rotation)

* **코드:**
```javascript
const model = M4.multiply(M4.translate(0, 1.9, 0), M4.rotateY(time * 0.8));

```


* **수식:** $\mathbf{Model} = \text{Translate} \cdot \text{Rotate}$
* **적용 순서:** $\text{Rotate(회전)} \rightarrow \text{Translate(이동)}$
* **원리 설명:**
1. 원점에 있는 구체 자체에 오른쪽의 **회전 변환($\text{Rotate}$)이 먼저 적용**되어 중심축을 기준으로 제자리에서 돈다.
2. 회전된 상태의 구체가 왼쪽의 **이동 변환($\text{Translate}$)에 의해 위($Y = 1.9$)로 이동**한다.
3. 결과적으로 구체는 높이 $1.9$ 지점에서 제자리 회전하는 **자전** 운동을 보인다.



---

### ② 궤도 회전 (공전, Revolution)

* **코드:**
```javascript
const model = M4.multiply(M4.rotateY(time * 0.8), M4.translate(0, 1.9, 0));

```


* **수식:** $\mathbf{Model} = \text{Rotate} \cdot \text{Translate}$
* **적용 순서:** $\text{Translate(이동)} \rightarrow \text{Rotate(회전)}$
* **원리 설명:**
1. 오른쪽의 **이동 변환($\text{Translate}$)이 먼저 적용**되어 구체가 원점에서 위($Y = 1.9$)로 이동하며 회전 중심축으로부터 이격된다.
2. 축에서 떨어진 상태에서 왼쪽의 **회전 변환($\text{Rotate}$)이 적용**되어, 원점(Y축)을 기준으로 구체 전체를 돌린다.
3. 결과적으로 구체는 중심축과의 거리를 유지한 채 큰 원을 그리며 도는 **공전** 운동을 보인다.



---

## 4. 요약 및 결론

* Matrix-Vector 곱셈의 특성상 **오른쪽에 위치한 변환이 먼저 수행**된다.
* 이동 후 회전을 적용($\text{Rotate} \cdot \text{Translate}$)하면 물체가 회전축으로부터 떨어진 상태로 회전하므로 **공전 효과**가 발생한다.






# 8단계 코드
#version 300 es
precision highp float;

in vec3 vColor;
in vec3 vNormal;

uniform float uTime;
out vec4 fragColor;

void main() {
  vec3 N = normalize(vNormal);
  vec3 L = normalize(vec3(0.45, 0.8, 0.35));

  float diff = max(dot(N, L), 0.0);
  float toonDiff = floor(diff * 4.0) / 4.0; // 계단식 음영 적용

  fragColor = vec4(vColor * (0.3 + 0.7 * toonDiff), 1.0);
}



#실습2

① 의도 — 무엇을 만들고 싶었는가
어떤 행성을 만들려고 했습니까?

신비로운 분위기를 가지면서 스스로 빛을 내는 독특한 행성을 만들고자 했습니다.
일반적인 행성처럼 외부에서 들어오는 빛을 단순히 반사하는 모습이 아니라, 행성 표면에서 오로라와 같은 빛이 직접 발생하는 것처럼 표현하고 싶었습니다. 또한 표면을 단순한 단색으로 만들지 않고, 울퉁불퉁한 지형과 불규칙한 무늬를 추가하여 실제로 존재할 것 같은 입체적인 행성을 표현하고자 했습니다.

왜 그렇게 정했습니까? 보는 사람이 무엇을 느끼길 바랐습니까?

처음 보는 순간 “이런 행성이 실제로 존재할까?”라는 호기심이 생기도록 만드는 것을 목표로 했습니다.
특히 보라색과 푸른색 계열의 암석 표면 사이에서 빛나는 오로라를 통해 신비롭고 아름답고 오묘한 느낌을 전달하고 싶었습니다. 단순히 현실에 존재하는 행성을 재현하기보다는, 실제 우주에서는 발견하지 못한 상상 속의 새로운 행성을 만들어 보는 것에 의미를 두었습니다.

예시와 무엇을 다르게 하려고 했습니까?

기존 예시의 행성은 일반적인 조명에 의해 밝고 어두운 부분이 구분되는 방식이었다면, 저는 행성 자체에서 빛이 발생하는 것처럼 보이는 효과를 추가하고자 했습니다.

또한 행성 표면에 단순한 색상이나 반복적인 무늬만 사용하는 대신, Noise와 FBM을 이용해 표면의 높낮이와 불규칙한 질감을 만들었습니다. 이를 통해 같은 패턴이 반복되는 인공적인 느낌을 줄이고 자연스럽게 울퉁불퉁한 행성 표면을 표현했습니다.

행성 주변을 도는 위성 역시 일반적인 회색이나 갈색의 위성이 아니라 핑크색과 민트색을 조합한 독특한 가스 행성으로 표현했습니다. 이를 통해 두 천체 모두 현실에서 쉽게 볼 수 없는 색과 형태를 가지도록 하여, 전체적으로 신비롭고 호기심을 자극하는 우주 공간을 만들고자 했습니다.

② 방법 — 어떻게 만들었는가

행성의 표면을 단순한 색으로 표현하지 않고 자연스러운 지형과 움직이는 오로라, 불규칙한 가스 줄무늬를 표현하기 위해 Noise, FBM(Fractal Brownian Motion), Domain Warp, 삼각함수(sin) 등을 사용했습니다.

1. 암석 행성의 울퉁불퉁한 표면

먼저 noise3()를 이용해 공간상의 각 위치마다 서로 다른 값을 만들고, 이를 여러 크기의 노이즈로 반복해서 합산하는 FBM을 사용했습니다.

float fbm(vec3 p) {
    float v = 0.0;
    float a = 0.5;

    for (int i = 0; i < 6; i++) {
        v += a * noise3(p);
        p *= 2.02;
        a *= 0.5;
    }

    return v;
}

여기서 여러 크기의 노이즈를 합치기 때문에 큰 지형의 형태와 작은 돌기까지 동시에 표현할 수 있습니다.
또한 large, medium, small 세 가지 크기의 FBM을 조합하여 행성 표면의 높이를 계산했습니다.

float h =
    large * 0.62 +
    medium * 0.28 +
    small * 0.10;

이렇게 계산한 h값에 따라 어두운 암석부터 밝은 암석까지 색을 다르게 적용했습니다. 따라서 행성 표면에 단순한 색 변화가 아니라 높낮이가 있는 울퉁불퉁한 지형처럼 보이는 무늬가 만들어집니다.

2. 행성에서 빛나는 오로라

행성의 가장 중요한 특징인 자체 발광 효과는 FBM과 sin()을 이용해 만들었습니다. 먼저 행성 표면의 좌표를 warp()로 변형한 뒤 FBM을 적용하여 일정한 원형 띠가 아니라 휘어지고 끊어지는 불규칙한 오로라 띠를 만들었습니다.

vec3 ap = warp(
    vSurf * 1.65 +
    vec3(0.0, 0.0, uTime * 0.045)
);

float ribbon = fbm(ap);

그 다음 smoothstep()을 이용해 특정 범위의 노이즈 값만 선택하여 오로라가 나타나는 부분을 만들었습니다.

float band =
    smoothstep(0.43, 0.52, ribbon) *
    smoothstep(0.79, 0.56, ribbon);

그리고 uTime을 계산에 포함하여 시간이 지나면서 오로라의 위치와 밝기가 변하도록 했습니다.

float shimmer =
    0.72 +
    0.38 * sin(uTime * 1.15 + ribbon * 10.0);

즉, FBM은 오로라의 불규칙한 형태를 만들고, sin()과 uTime은 빛이 시간에 따라 움직이고 깜빡이는 효과를 만드는 역할을 합니다. 이 과정을 통해 행성 내부에서 빛이 발생하는 것처럼 보이게 했습니다.

3. 핑크·민트 위성의 불규칙한 줄무늬

두 번째 행성은 단순히 sin()만 사용하면 일정한 간격의 줄무늬가 반복되기 때문에, 먼저 구면의 세로 위치를 나타내는 **위도 lat**을 계산했습니다.

float lat = asin(clamp(vSurf.y, -1.0, 1.0));

그리고 기본 줄무늬에 FBM으로 만든 largeFlow와 mediumFlow를 더했습니다.

float stripePhase =
    lat * 20.0
    + (largeFlow - 0.5) * 5.2
    + (mediumFlow - 0.5) * 2.0;

float stripeWave =
    0.5 + 0.5 * sin(stripePhase);

여기서 lat * 20.0이 기본적인 가로 줄무늬를 만들고, largeFlow와 mediumFlow가 줄무늬의 위치와 경계를 조금씩 흔들어 줍니다. 따라서 줄무늬가 기계적으로 동일한 간격으로 반복되지 않고 가스가 흐르는 것처럼 휘어지고 불규칙한 형태가 됩니다.

마지막으로 핑크 계열의 행성 색상과 민트·청록 계열의 줄무늬 색상을 섞었습니다.

vec3 stripeDark  = vec3(0.22, 0.54, 0.50);
vec3 stripeLight = vec3(0.67, 0.94, 0.82);

albedo = mix(
    albedo,
    stripeColor,
    brokenStripe * 0.78
);

이를 통해 핑크색 바탕 위에 민트색 가스가 흐르는 듯한 줄무늬를 표현했습니다.

③ 뜻대로 안 된 부분과 수정한 방법

이 부분도 보고서에 넣으면 좋아. 실제 제작 과정에서 발생한 문제를 보여주기 때문에 오히려 보고서가 더 구체적으로 보여.

바닥의 색이 행성의 움직임에 따라 변하는 문제가 발생했습니다.

처음에는 행성과 바닥을 같은 Fragment Shader에서 처리했기 때문에, 행성에 적용한 FBM과 조명 계산이 바닥에도 적용되는 문제가 있었습니다. 그 결과 바닥이 행성의 절차적 무늬와 조명 계산의 영향을 받아 색이 계속 변하는 것처럼 보였습니다.

이를 해결하기 위해 uObjectType이라는 값을 추가하여 현재 렌더링하는 대상이 행성인지 바닥인지 구분하도록 수정했습니다.

uniform float uObjectType;

바닥을 그릴 때에는 행성용 Noise와 오로라 계산을 적용하지 않고 지정된 색상을 그대로 출력하도록 했습니다.

if (uObjectType > 0.5) {
    vec3 floorColor = vec3(0.42, 0.50, 0.62);
    fragColor = vec4(floorColor, 1.0);
    return;
}

이를 통해 행성에는 복잡한 절차적 셰이더를 적용하면서도 바닥은 일정한 색상을 유지하도록 수정했습니다.
